## 논의 내용
역할은 위에 적은 대로 별 이견 없이 정함. 도윤이 QA랑 문서를 같이 맡는 게 많지 않냐고 해서 회의록은 은정이 계속 쓰기로 함.

기술 스택에서 준호가 React Native를 제안했다. 웹 경험이 있으니 바로 시작할 수 있다는 이유. 하은은 Flutter 쪽 디자인 결과물이 더 깔끔하다고 했지만 오늘은 일단 RN으로 시작해 보기로 함.
백엔드는 민재가 Spring Boot에 MySQL, 다들 수업에서 써봐서 이견 없음.

로그인 방식은 도윤이 학교 이메일로 인증 메일 보내는 방식을 제안. 학생만 쓰게 하는 게 핵심이라 다들 동의.
결제는 민재가 토스페이먼츠 테스트 키로 앱 안에서 결제까지 붙여보자고 함. 은정은 범위가 너무 커질까 걱정했지만 일단 넣어 두고 나중에 다시 보기로.

## 결정 사항
- 프론트엔드는 React Native로 시작한다
- 백엔드는 Spring Boot, DB는 MySQL을 쓴다
- 로그인은 학교 이메일 인증 방식으로 한다
- 결제는 토스페이먼츠로 앱 안에서 처리한다
- 판매자와 구매자 대화는 WebSocket 실시간 채팅으로 만든다
- 매물 사진은 최대 5장까지 올릴 수 있게 한다
- 서버는 AWS EC2 프리티어에 올린다
- 거래 요청과 새 메시지 알림은 FCM 푸시로 보낸다
